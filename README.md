# dsh-mcp-tool

MCP-серверы, которые включаются пресетом рабочей папки.

Реестр серверов заводится глобально и ни один из них не запущен. **Пресет** говорит,
какие серверы включены; **рабочая папка** получает пресет. Включённый сервер агент
поднимает сам, когда он ему понадобился (`mcp_load`), и останавливает, когда перестал
быть нужен (`mcp_release`). Процесс также завершается сам по простою. Сервер со способом
загрузки «всегда запущен» стартует вместе с плагином везде, где он включён, и не
выгружается по простою.

Устройство плагина, сущности и жизненный цикл — [docs/DESIGN.md](docs/DESIGN.md).

## Что видит агент

- `mcp_servers` — какие серверы включены в его папке, их статус, способ загрузки и число
  инструментов (для остановленного сервера — по сохранённому каталогу, без запуска
  процесса).
- `mcp_load { server }` — поднять сервер; возвращает имена и входные схемы инструментов.
  Инструменты появляются как `mcp__<server>__<tool>` со следующего шага модели.
- `mcp_release { server }` — отпустить сервер; при нулевом счётчике процесс завершается
  (для «всегда запущенного» сервера процесс остаётся).

Все три инструмента скрыты в папках, где ничего не включено. Плюс секция системного
промпта с той же картиной. Если сервер выключен пресетом, но его инструмент уже попал в
список модели, вызов всё равно будет отклонён с подсказкой включить сервер в настройках.

## Что видит человек

- **Настройки → MCP Tool** — страница плагина:
  - **MCP** — реестр серверов (stdio и streamable-http), добавление и правка формой прямо
    на странице: «Изменить» разворачивает поля внутри карточки сервера, у каждого сервера
    способ загрузки: «Ленивая загрузка» или «Всегда запущен»;
  - **Пресеты** — `default` (действует во всех папках без своего пресета) и именованные
    пресеты; плашка пресета разворачивается в список серверов с переключателем
    Вкл / Выкл / Наследовать, где «Наследовать» берёт значение из `default`;
  - **Рабочие папки** — все workspace'ы DSH и папки с назначенным пресетом; выбор
    пресета для папки.
- **Чип в строке ввода** — `MCP · <пресет>` рядом с полем ввода: быстрый выбор пресета
  для папки открытого диалога. Показ чипа включается и выключается на странице настроек.
- **Серверы из настроек DSH.** Серверы, добавленные в `Настройки → MCP` самого DSH,
  подхватываются автоматически при открытии страницы плагина: появляются в реестре с
  пометкой «из настроек», выключенными в `default`, и не редактируются здесь — их правят в
  настройках DSH. Удалённые из настроек исчезают из реестра вместе со строками в пресетах.
  Пресет решает, какие их инструменты видит агент в этой папке. Если сервер в настройках
  выключен, плагин поднимает его по требованию (`mcp_load` или кнопка «Запустить по
  требованию») и гасит по `mcp_release` или после 10 минут простоя; сервер, поднятый самим
  DSH, плагин не останавливает. Способ управления выбирается в шапке страницы сегментами
  «Авто | Тумблер | Свой процесс», под ними подпись, объясняющая выбранный режим
  (по умолчанию — «Авто»):
  - **Тумблер** — плагин переключает `enabled` записи в настройках DSH и ждёт, пока менеджер
    поднимет или погасит процесс: владелец сервера остаётся штатный;
  - **Свой процесс** — плагин поднимает собственное соединение в изолированном scope и не трогает
    запись в настройках: на время работы она гасится, а при остановке включается обратно,
    если была включена; инструменты проецируются агентам с учётом пресета;
  - **Авто** — по серверу: гасит и поднимает через менеджер то, что в настройках выключено,
    и монтирует своё соединение для включённого (его имя занято в корневом scope).
- Кнопки и переключатели страницы повторяют нативную малую кнопку оболочки: та же высота,
  шрифт, радиус и волосяная обводка; заливка — только у «действенных» кнопок.
- Интерфейс на русском и английском.

## Установка

Плагин — обычный DSH-bundle:

```
dsh plugin --profile <profile> add <path-to-this-repo>
```

Например, при клоне в `D:\Projects\dsh-mcp-tool`:

```
dsh plugin --profile desktop add D:\Projects\dsh-mcp-tool
```

Профиль для разработки: `mcp-tool-dev` (`--from-default-profile web`).

## Хранение

Один файл `$DSH_HOME/storages/mcp_tool.json` (общий для всех профилей): серверы,
пресеты, назначения папок и глобальная настройка чипа. Живое состояние (процессы,
счётчики) не сохраняется. Записи, зеркалированные из настроек DSH, помечены
`origin: "profile"`.

## Доступ к маршрутам

Страница плагина общается с хостом по своим роутам `/dsh-mcp-tool/*`. Каждый запрос
сначала проходит штатную проверку DSH — `ctx.connection.requestRejection(req)`: без
браузерного токена `401`, при чужом Host/Origin `403`, в обоих случаях реестр не
трогается. Мутации дополнительно требуют заголовок `x-dsh-mcp-tool: 1` и
`content-type: application/json`, поэтому кросс-сайтовая форма не может
зарегистрировать сервер.

## Разработка

```
node .\node_modules\typescript\bin\tsc -p tsconfig.json        # хост
node .\node_modules\typescript\bin\tsc -p tsconfig.client.json # клиент (ESM)
node scripts\wrap-client.mjs                                   # обёртка в window.__ModuleLoader__
node --test --test-isolation=none "test/*.test.mjs"            # тесты
```

`npm install` в этом окружении — только с кэшем внутри проекта:
`npm install --cache .npm-cache`.

Диагностика: `MCPTOOL_DEBUG=1`, запись в файл — `MCPTOOL_LOG=<путь>`.

## Приёмка на реальном сервере

```
set MCPTOOL_ACCEPT_COMMAND=C:\tools\my-server.exe
set MCPTOOL_ACCEPT_ARGS=--mcp
node test\accept-stdio.mjs
```

Скрипт копирует сервер во временный каталог, поднимает его по stdio, проверяет
`tools/list`, при желании один вызов инструмента и завершение процесса после закрытия
клиента. Настройка — переменными окружения:

| переменная | смысл |
| --- | --- |
| `MCPTOOL_ACCEPT_COMMAND` | исполняемый файл сервера (обязательно) |
| `MCPTOOL_ACCEPT_ARGS` | аргументы через пробел, по умолчанию `--mcp` |
| `MCPTOOL_ACCEPT_COPY` | дополнительные файлы рядом с сервером, через `;` |
| `MCPTOOL_ACCEPT_EXPECT_TOOLS` | ожидаемое число инструментов |
| `MCPTOOL_ACCEPT_TOOL` | инструмент для проверочного вызова |
| `MCPTOOL_ACCEPT_TOOL_ARGS` | JSON с аргументами этого вызова |

Запускайте на копии сервера и в офлайн-режиме, если он умеет: скрипт не должен трогать
живые данные.
