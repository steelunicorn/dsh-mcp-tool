# dsh-mcp-tool — устройство плагина

Плагин DSH управляет MCP-серверами на уровне рабочих папок. Реестр серверов заводится
глобально, но ни один сервер не работает постоянно: **пресет** задаёт, какие серверы
включены, **рабочая папка** получает пресет, и сервер запускается только тогда, когда он
нужен агенту в этой папке.

Ключевая идея: описание сервера и его включённость разделены. Реестр хранит, *как*
запускать сервер. Пресет хранит, *какие* серверы разрешены. Папка выбирает пресет.
Агент видит только разрешённые серверы и сам решает, когда поднять процесс.

## 1. Сущности

**Server (реестр, глобально).** Описание MCP-сервера без признака «включён», но со
способом загрузки:

```json
{
  "name": "my-server",
  "description": "Some terminal emulator",
  "transport": "stdio",
  "loadMode": "lazy",
  "command": "C:\\tools\\my-server.exe",
  "args": ["--mcp"],
  "env": {},
  "cwd": null,
  "toolCallTimeoutMs": 60000
}
```

`transport: "http"` — `url` + `headers` вместо команды. Секреты — `${credential:NAME}`
(основной путь); литеральный секрет разрешён, интерфейс показывает предупреждение.

`loadMode`:

- `lazy` (по умолчанию) — процесс поднимается по `mcp_load` и завершается по
  `mcp_release`, простою или выгрузке плагина;
- `eager` — процесс поднимается при старте плагина везде, где сервер разрешён, не
  выгружается по простою и не вытесняется лимитом живых процессов; `mcp_release` его не
  останавливает (агент только перестаёт быть держателем).

**Preset (глобально).** `{ name, rows: { <server>: "on" | "off" | "inherit" } }`.
`default` — единственный обязательный пресет; в нём `inherit` приводится к `on`.
Отсутствие строки означает `inherit`, в `default` — `on`, поэтому только что добавленный
сервер доступен везде, пока его не выключат. Именованные пресеты наследуют строки
`default`, если строка не задана.

**Folder assignment.** `{ path, preset }`, `path` — канонический абсолютный путь
(Windows: регистронезависимо, разделители нормализованы). Папка берёт ближайшее
назначение среди своих предков (граница сегмента пути); назначение `default`
эквивалентно отсутствию и хранится как удаление записи.

**Разрешение для агента.** `cwd` сессии → пресет (`folder` или `default`) → строки:
`on` включён, `off` выключен, `inherit`/отсутствие — значение из `default`. Пустой список
означает, что инструменты плагина агенту не показываются (`when: false`), а секция
промпта пустая.

**Сессии без живого агента.** `cwd` берётся из живого агента (`ctx.agents.get`, затем
скан `ctx.agents.list()` по `agent.id` / `session.header.cwd`), иначе из подсказки `?cwd=`
браузера (`useSessions` знает `state.byId[sessionId].cwd`). Если интерфейс не прислал
`sessionId` (страница Settings живёт вне сессии), host подставляет самый свежий живой
агент с непустым cwd (`activeSessionId`). `/activate` тоже принимает `cwd`, а держателем
сервера, запущенного из интерфейса, становится `agent.id`, иначе `sessionId` — сессия
живёт между ходами, поэтому сервер не отпускается сразу после клика.

## 2. Хранение

`storageDomain`: домен `mcp_tool`, `version: 1`, `layout: "single"` → человекочитаемый
атомарный JSON `$DSH_HOME/storages/mcp_tool.json`, общий для всех профилей. Имя домена
обязано соответствовать `UNIT_NAME_RE` хоста, поэтому подчёркивание, а не дефис:
`mcp-tool` отвергается с `invalid unit name 'mcp-tool'`.

- `servers` — `<name> → Server`
- `presets` — `<name> → Preset`; `default` может отсутствовать в файле, но синтезируется
  при чтении и отдаётся первым элементом списка, чтобы страница всегда имела вкладку, на
  которую можно вернуться
- `workspaces` — `<path> → { path, preset, updatedAt }`
- `global` — `{ showChip: boolean }`

На диске json-backend держит конверт
`{ unit: { name: "mcp_tool", version: 1 }, global: <объект|null>, tables: { servers, presets, workspaces } }`;
`servers` сортируется по имени, пресеты — `default` первым, затем по имени, папки — по
пути.

Список workspace'ов для вкладки «Рабочие папки» берётся из сервиса `workspaceRegistry`.
Сервис читается через `ctx.get('workspaceRegistry')` внутри `try`, а не через
`ctx.workspaceRegistry`: Cordis бросает `cannot get property "workspaceRegistry" without
inject` на прямой доступ к незадекларированному сервису, а объявлять его в `inject`
нельзя — плагин перестал бы стартовать в профилях без web-слоя.

Живое состояние (процессы, refcount, последние вызовы) не персистится: после перезапуска
DSH все lazy-серверы снова неактивны, eager поднимаются при старте плагина. При
возобновлении сессии ничего не восстанавливается.

## 3. Жизненный цикл сервера

1. `mcp_load {server}` — агент просит сервер. Проверка: сервер есть в реестре и включён
   пресетом его папки. Иначе агенту возвращается ошибка, без тихих ретраев.
2. Первая загрузка: `ctx.mcpManager.register(name, entry)`, статус из `mcpManager.watch`;
   инструменты появляются в каталоге как `mcp__<name>__<tool>`. Один процесс на сервер,
   refcount по агентам.
3. Видимость: инструменты lazy-сервера видны только агентам, которые его загрузили; чужим
   агентам ставится `restrict({ deny: [...] })` в их scoped ctx, при отпускании
   ограничение снимается. Инструменты eager-сервера видны каждому агенту, в чьей папке
   сервер включён пресетом.
4. `mcp_release {server}` — refcount--; при нуле регистрация снимается, процесс
   завершается. Для eager-сервера возвращается `released: false`, он продолжает работать.
5. Автоматика: `tools.guard` на вызовах `mcp__<name>__*` обновляет `lastUsed`; таймер раз
   в 30 с отпускает lazy-сервер, если нет вызовов 10 минут и нет вызова в полёте. Максимум
   3 живых lazy-процесса — при превышении выгружается самый давний; eager не вытесняется и
   в лимит не входит. По `agent/disposed` отпускаются все загрузки этого агента.
6. Смена пресета папки или `loadMode` применяется на ближайшей границе шага:
   `backend.changed()` пересчитывает eager-закрепления (сервер больше не eager →
   `unpinEager`, сервер стал eager → `loadEager` для живых агентов). Lazy-серверы,
   попавшие под `off`, продолжают работать, пока их держит агент, но перестают быть видны
   тем, кому пресет их выключил.

## 4. Инструменты и промпт

Модельные тексты — английский, интерфейс — ru/en.

- `mcp_servers` — `{}` → включённые серверы для этой папки: имя, описание, транспорт,
  `loadMode`, статус (`inactive|starting|ready|failed`), число инструментов, держатели.
- `mcp_load {server}` — идемпотентно; возвращает имена инструментов и их input-схемы.
  Ошибка активации отдаётся текстом как есть (в том числе `isError` от сервера).
- `mcp_release {server}` — идемпотентно; возвращает, остановлен ли процесс.

Все три регистрируются с `when`, зависящим от политики текущего агента: в папке без
включённых серверов они не видны. Дополнительно публикуется секция системного промпта
(order 3110) с той же картиной: какие серверы включены, какой пресет действует, что
грузить через `mcp_load` и отпускать через `mcp_release`.

Конвенция схем: в `parameters` поля помечаются `required: true`; в `output.schema` так
нельзя — хост отвергает `schema.properties.<x>.required is not supported on type ...`.
Там `required` — массив имён на уровне объекта, а `additionalProperties` допустим только
булев.

## 5. Интерфейс

Канал host → client: свой `ctx.webServer.register({ kind: 'prefix', path: '/dsh-mcp-tool' })`
плюс `fetch` из клиента; живые статусы страница получает опросом `/state` раз в 3 секунды.

Роуты: `GET /state`, `GET /workspaces`, `GET /folder-exists`, `POST /server`,
`/server/delete`, `/preset`, `/preset/delete`, `/folder`, `/folder/delete`, `/settings`,
`/activate`. Все мутации требуют заголовок `x-dsh-mcp-tool: 1` и `content-type:
application/json`: plugin-роуты идут мимо cookie-гейта, иначе cross-site form-POST мог бы
зарегистрировать сервер с произвольной командой.

- **Секция Settings** (`settings.section` + `settings.section.icon`, id `mcp-tool`) —
  основное место настройки. Раскладка — колонка: статичная шапка (подпись, глобальный
  переключатель «Показывать чип в диалоге», вкладки) и отдельная прокручиваемая область
  под ней, поэтому скролл не уезжает под переключатель.
  - **MCP** — реестр: строка «Добавить сервер» и форма в потоке страницы (не оверлеем):
    имя, описание, транспорт, способ загрузки, команда/аргументы/env/cwd либо
    URL/заголовки, таймауты. Строка сервера показывает статус, транспорт и способ
    загрузки, «Изменить» / «Удалить».
  - **Пресеты** — вертикальный список плашек одинаковой ширины (`default` первой);
    нажатие разворачивает под плашкой полный список серверов с переключателями
    Вкл / Выкл / Наследовать (в `default` — только Вкл / Выкл) и кнопкой удаления пресета.
    Развёрнута одна плашка за раз, ниже — создание пресета. Изменения сохраняются сразу.
  - **Рабочие папки** — все workspace'ы DSH плюс папки с назначенным пресетом; для каждой
    строки выбор пресета (`default` = снять назначение). Ручного добавления пути нет:
    список собирается из workspace'ов, а папка без workspace назначается чипом.
- **Чип в composer** (`conversation.input.right`): показывается всегда, если включён
  глобальный переключатель; подпись `MCP` на `default` и `MCP · <пресет>` на именованном.
  Поповер — выбор пресета для папки текущего диалога без открытия настроек; он измеряет
  viewport и открывается вверх, если снизу мало места.
- Локали ru/en через `ctx.locale.register(ns, locale, dict)`; `locale/en.json` и
  `locale/ru.json` для `meta.title` / `meta.description`. Стили — инлайн и токены
  `--dsw-alias-*` (label-primary/secondary, border-l1/l2, bg-layer-1/2/3, brand-primary,
  label-primary-inverted, bg-mask-1, button-ghost-active-fill) с светлыми fallback'ами,
  чтобы отсутствие переменной не давало белую карточку в тёмной теме. Строки серверов,
  пресетов и папок собственной подложки не имеют — фон совпадает с фоном окна настроек,
  различие даёт только волосяная рамка. Подписи режимов загрузки — «Ленивая загрузка» /
  «Всегда запущен».

## 6. Пакет и сборка

Один пакет `dsh-mcp-tool`, bundle id `mcp-tool`. TypeScript, без бандлера для хоста:
`tsc` → `lib/`. Клиент: `tsc` (ESM) + `scripts/wrap-client.mjs`, который оборачивает
вывод в `window.__ModuleLoader__.load({ id, factory(require) { ... } })`. JSX нет — `h()`.
`dsh.client.inject` — только `@deepseek-ai/dsh-client-runtime` и
`@deepseek-ai/dsh-client-locale`: бандл требует лишь сиды react/react-dom.

```
package.json         exports ., ./client, ./locale/*.json; dsh.bundle.patch, dsh.client
cordis.patch.yml     insert: [{ id: mcp-tool, name: 'dsh-mcp-tool' }]
src/index.ts         apply: домен, инструменты, промпт, роуты, трекинг агентов, eager, sweep
src/host.ts          адаптеры хоста: mcpManager → ManagerPort, tools → CatalogPort, entry/статусы
src/store.ts         реестр серверов, пресеты и назначения папок (zod-схемы, домен mcp_tool)
src/policy.ts        разрешение пресета папки и строк пресета в список серверов
src/runtime.ts       пул: register/unregister, refcount, eager-закрепление, скрытие, idle/LRU
src/tools.ts         mcp_servers / mcp_load / mcp_release с when по пресету
src/prompt.ts        секция системного промпта (order 3110)
src/http.ts          /dsh-mcp-tool/* (state, workspaces, servers, presets, folders, settings, activate)
src/client/client.ts страница Settings, иконка и чип с поповером (один файл, без value-импортов)
test/*.test.mjs      node --test: политика, пул, стор, HTTP, плагин на фейковом ctx, клиентский артефакт
test/fixtures/       stdio-эмулятор MCP-сервера на @modelcontextprotocol/sdk
test/accept-stdio.mjs   ручная приёмка на реальном stdio-сервере (путь из MCPTOOL_ACCEPT_COMMAND)
```

Установка: `dsh plugin --profile <профиль> add <путь-к-репозиторию>`. Сборка коммитится в
`lib/`, поэтому плагин работает из клона без сборки.

## 7. Проверка

1. Юнит-тесты на фейковом ctx — 68 тестов
   (`node --test --test-isolation=none "test/*.test.mjs"`): политика (6), пул (11),
   стор (11), HTTP (21), плагин целиком на фейковом хосте (16), плюс клиентский артефакт
   `lib/client.js` под стаб-загрузчиком (2). Проверяются, в частности: `apply`
   регистрирует секцию Settings, её иконку и чип, обе локали; `default` включает
   добавленный сервер везде, именованный пресет выключает его только в назначенных папках,
   `inherit` читает `default`; eager-сервер стартует с плагином и не отпускается
   `mcp_release`, смена `loadMode` на `lazy` снимает закрепление; выгрузка плагина
   останавливает процессы; активация из интерфейса и разрешение по `?cwd=` работают.
2. Эмулятор stdio-сервера на `@modelcontextprotocol/sdk` — фикстура `test/fixtures/`.
3. Приёмка на реальном stdio-сервере: `test/accept-stdio.mjs` копирует исполняемый файл (и
   файлы из `MCPTOOL_ACCEPT_COPY`) во временный каталог, поднимает его с аргументами из
   `MCPTOOL_ACCEPT_ARGS`, проверяет `tools/list`, при заданных переменных — один вызов
   инструмента, и завершение процесса по pid после `close`. Скрипт ничего не знает про
   конкретный сервер: проверяется оркестрация (старт, каталог, вызов, остановка).
4. Диагностика: `MCPTOOL_DEBUG=1`, запись в файл — `MCPTOOL_LOG=<путь>`.

## 8. Границы

Входит: реестр stdio+http, пресеты с наследованием, назначение пресета папке, eager и lazy
загрузка, мета-инструменты, отпускание, изоляция видимости, страница Settings, чип в
composer, локали ru/en.

Не входит: импорт серверов из профиля DSH, OAuth/DCR, фильтры инструментов сервера,
группы серверов, синхронизация настроек, CLI.

## 9. Ограничения среды

- Headless-профиль для модельного e2e не подходит: плагин ждёт сервисы `mcpManager` и
  `webServer`, которых там нет (`pending (waiting for services: ...)`), а провайдер
  `deepseek-account` требует входа (`ACCOUNT_SIGN_IN_REQUIRED`). Полная проверка возможна
  только в профиле с web-приложением и живой сессией.
- `--dump-config` перезаписывает `cordis.yml` профиля и для профиля `desktop` отклоняется
  (`profile "desktop" is managed exclusively by the Electron application`); dev-профиль
  создаётся из шаблона (`--from-default-profile web`).
- Клиентская половина раздаётся combo-бандлом (`plugins/??...,dsh-mcp-tool/client.js`);
  прямой `GET /plugins/<имя>/client.js` отдаёт 404, это не путь раздачи.
- `npm install` в этом окружении — только с кэшем внутри проекта:
  `npm install --cache .npm-cache`.
